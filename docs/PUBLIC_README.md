# 元器件管理（component_management）

一个**完全离线**的电子元器件库存管理小工具：把 BOM 与库存对起来，算清"要买什么、买多少"，
把到货入库，领料出库，全程留痕。**除 Electron 外零第三方依赖**，不需要联网、不需要数据库。

> 这个仓库是**脱敏快照**（单次初始提交，无历史）：去掉了公司内部文件名、本机路径与协作过程记录。
> 原本地开发仓库仍是完整的（35+ 次提交）。因此本仓库不含公司 BOM 样本，
> 依赖这些样本的测试被移到 `tests/local_only/`，公开版只跑不依赖公司数据的测试。

## v1.1.0 更新（2026-10-17）

- **检索与筛选**：库存页/领料页都可按 值/型号/封装/库位 搜索，并支持分类、封装、耐压、只看低库存筛选；
  检索带**相似产品**能力：`0.1uF` 与 `100nF`、`4K7` 与 `4.7kΩ`、`±1%` 与 `+/-1%`、全角 `１００ｎＦ`、`SOT23` 与 `SOT-23`
  都视为同一种写法；多关键字是 **AND**（每个词都要命中），结果按"越精确越靠前"排序；搜索框按 Enter 立即检索。
- **领料动线简化**：库存页行内「领料」直接跳到领料页并预选该器件；出/入库后保留检索/筛选状态。
- **对账单入库体验**：解析提示收进折叠区（不再顶动表格）、疑似行写清"对账单这一行 vs 库里候选"、
  裁决后就地反馈并可改选、重复提交幂等。
- **稳定性**：单实例（防多开）；检索请求竞态防护（晚到旧响应不覆盖新结果）；入库/删除/恢复等危险操作防重入。
- **工程**：架构分层与依赖规则写入 `docs/architecture.md` 并由 `tests/test_architecture.js` 强制；
  公共 API/界面行为不变，升级无需迁移数据。

## 它解决什么问题

手工用 Excel 管元器件，最常见的三件事都很费神、也最容易出错：

1. **重复采购** —— 库里明明有 100nF，却因为名字/封装写法不同又买一批。
   本工具用一张"判定键"表（值 · 封装 · 耐压 · 材质 · 容差）判定**同一种料**，并对单位做归一化
   （`0.1uF` 与 `100nF` 是同一种）。
2. **缺口算错** —— 需要 24 个、库存 3 个，该买的是 **21** 个（不是 24）。
   缺口语义在规格里被冻结，并有验收标准钉住。
3. **数量变动查不清** —— 每个数量变化都写一条变动记录（谁、何时、为什么、关联哪份单），
   `movements.json` 就是账本。

## 功能一览

| 页面 | 做什么 |
|---|---|
| **库存** | 列出全部器件、低库存高亮、排序、进详情看变动历史；**检索（含相似产品：`0.1uF` 也能搜到 `100nF`、`4K7`↔`4.7kΩ`）+ 分类/封装/耐压/低库存筛选**，结果实时收窄 |
| **导入 BOM** | 解析 `.xlsx` / `.xls` / `.csv`，**人工核对表**逐条确认后入库（不提供"一键静默导入"） |
| **按对账单入库** | 直接读立创商城「物料明细对账单」`.xls`：解析 H–L 列 → 与库对账（命中/疑似/新增）→ **疑似必须人工裁决**（裁决后有「已选择」就地反馈，点错可改选）→ 入库；**核对表可人工修改**（本次入库量、值/容差/耐压/封装/型号），改动随决定提交并留痕；重复提交有幂等闸门 |
| **比对** | BOM + 套数 → 够用 / 缺料 / 疑似三组，给出**缺口**合计；**全程只读**（比对前后库文件字节一致） |
| **手动录入** | 单条录入/编辑；同规格自动累加而不是重复建条；值留空时保存前用「型号」当值会**先询问**，取消就返回让你填值 |
| **领料** | 出库、按 BOM 领料（默认整单拒绝，可选部分领用）、查变动记录；手动出/入库自带**检索 + 分类/封装筛选**，库存页任一行可点「领料」直达并预选该器件 |
| **导出** | 立创商城配单 / 嘉立创 SMT 下单两种列结构（都能被立创识别） |
| **设置** | 14 类默认低库存阈值、数据目录 |
| **备份** | 整库备份 / 恢复（恢复前自动留一份当前状态） |

## 完全离线：不是口号，是机制

- CSP `connect-src 'none'`；主进程拦截 http/https/ws/wss/ftp 请求；拒绝开新窗口；导航白名单
- 渲染进程拿不到 Node（`contextIsolation` 开、`nodeIntegration` 关、无 `require`）
- 有测试扫描**全部源码**，确认没有任何对外发起请求的调用

## 使用

### 方式一：绿色版（解压即用）

1. 解压后双击 `start.cmd`。

### 方式二：生成安装包

```powershell
powershell -ExecutionPolicy Bypass -File tools\make_installer.ps1
# 只装程序本身（约 1 MB，要求机器已装 Electron）
powershell -ExecutionPolicy Bypass -File tools\make_installer.ps1 -WithElectron
# 连 Electron 运行时一起打包（约 350 MB，目标机无需预装）
```

产物是 zip，含 `install.cmd`（装到 `%LOCALAPPDATA%` + 建桌面快捷方式）、`start.cmd`、`uninstall.cmd`
（**卸载会先把 `data\` 搬出来再删程序，不会丢库**）、`README.txt`。纯文件安装，**不写注册表**。

### 前置

- Windows + Electron（全局 `npm i -g electron`，或本地有 `electron.exe`）
- 开发运行：`electron .`（在项目根目录）

## 数据放在哪

`data/` 下三个 JSON 文件，**没有数据库**：

| 文件 | 内容 |
|---|---|
| `parts.json` | 器件库（含库位、数据手册、替代料、阈值等） |
| `movements.json` | 变动记录（入库/出库/调整/初始化，含原因与单号） |
| `settings.json` | 分类默认阈值、数据目录等 |

写入一律走 `store.js`：**同目录临时文件 → rename 的原子写**，并保留备份；JSON 损坏会**抛错**而不是静默重写。

## 架构

```
src/
  main.js            Electron 主进程（窗口、离线拦截、文件对话框）
  preload.js         contextBridge 白名单（由 channels.js 派生，不写死数量）
  ipc/channels.js    IPC 通道唯一清单
  ipc/handlers.js    IPC 薄层（校验 → 调服务 → 原子落盘）
  services/          业务规则：store / bom_parser / compare / inventory / parts /
                     exporter（自写 xlsx 写入器）/ xls_biff（自写 BIFF8 读取器）/
                     lcsc_statement（对账单解析）/ statement_match / statement_commit /
                     low_stock / spec_parser / ids / table_header
renderer/
  index.html app.js style.css
  model/             纯规则层（无 DOM、无 require，可无头断言）
  pages/             每个页面一个文件，只做 DOM 装配
docs/
  spec.md            规格（WHAT，验收唯一信源）
  plan.md            方案（HOW：数据模型、IPC 契约、模块边界）
tools/               安装包生成、公开快照生成、文档一致性校验
tests/               35 个套件；tests/local_only/ 为依赖公司样本的套件
```

## 已知边界（诚实交代）

- 只做了 Windows 打包；安装包**未签名**（可能触发 SmartScreen 提示）
- 立创对账单只解析 **H–L 列**（商品类型/名称/型号/封装/数量）；**不使用位号**，也不抓页面
- 从型号/名称推断参数时**只提示、不自动落库**（"解析结果一律标建议"）
- 低库存判据是「库存 **低于** 阈值」（等于不算）
