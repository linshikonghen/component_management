1. **看板没有 open 任务**（当前 4 个全 done），所以**先建任务**：

## 五、项目硬约束（违反即返工）

| 约束 | 说明 |
|---|---|
| **零 npm 依赖** | 本机离线，`npm install` 装不上。除 Electron 外不引入任何第三方包 |
| **禁止任何网络请求** | 离线是硬需求（spec FR-6.1） |
| **比对绝不写库** | `compare.js` 不得 import 任何写函数；验收用「比对前后库文件字节比对」证明（spec FR-2.5） |
| **核对不可绕过** | 导入必须经人工核对界面，**不得提供一键静默导入**（spec FR-1.3） |
| **改的是「本次入库量」** | 核对阶段可改，但 `quantity_per_board`/`total_quantity` **只读**，**绝不回写 BOM 文件**（spec FR-1.6） |
| **数量变动必留痕** | 任何 `quantity` 变化都写 `movements.json`（spec FR-4.5） |
| **比对页禁放领料按钮** | 比对只读、领料改库，入口必须隔离（spec FR-7.6） |
| **渲染进程禁 `require('fs')`** | 一律走 IPC；数据写入只经 `store.js` 且**原子写**（临时文件 + rename） |
| 数据字段用 **snake_case** | 前后端字段名必须与 plan §6 契约逐字一致，禁止自转 camelCase |

> ⚠️ **改中文文件禁用 PowerShell 的 `Set-Content` / `-replace`**
> （按系统 ANSI 代码页读写，会破坏 UTF-8）。**本项目已因此毁过一次文档**：
> spec.md/plan.md 中文全变乱码、1088 字符不可逆丢失。用编辑工具，或
> `io.open(..., encoding='utf-8')`。

## 六、建议起点（二选一，按风险优先）

**方案 A（推荐）：先做 T13b — xlsx 写入器**

理由：这是**全工程最高风险点**。本项目**读** xlsx 已实测通过（纯 Node 解 zip +
`zlib`，无第三方依赖），但**写** xlsx 一行代码都没有——要手工拼 zip（CRC32、
local header、central directory）+ XML，**失败是静默的**（文件生成成功但内容坏 /
立创不认）。

T13b 不依赖 UI，做完就能回答"能不能写出立创认的 xlsx"。
**若失败 → 改导出 `.csv`**（立创明确支持），越早发现越省事。

> 注意：T13b 的验收是"导出后用**本项目自己的读取器**读回逐格比对"（plan §10.1 第 2 步），
> 所以要先把 xlsx **读取器**做出来（属 T3）。**先做 T3 再做 T13b**，或把最小读取器
> 并入 T13b——由你判断，但在任务里写明。

**方案 B：按 plan 顺序从 T1 开始**

T1 Electron 骨架 → T2 store.js → T3 bom_parser → …（依赖图见 plan §9）

无论选哪个，**都按 plan §9 的依赖图走**，不要跳步。
