## 八、关于 `auto_review_cmd`（用户提问 ④）

**它是什么**：工作区设置里的一条命令，`addmodel watch` 发现待审时自动调用，
用于**把评审自动派发给 reviewer**。

**机制**：

```
python -m addmodel watch
      ↓ 发现待审
读 settings.json 的 auto_review_cmd
      ↓ 替换占位符
{review_id} → R_xxx      {root} → 工作区路径
      ↓ 执行
auto-review.ps1 → 通知 mimo（或写入 review-inbox 转交文件）
```

**本工作区当前状态：该项为空**（`"auto_review_cmd": ""`）。后果：

| 有配置 | 空着（现状） |
|---|---|
| 提交评审后**自动**推送通知给 mimo | 提交后无人自动通知，需 mimo 自己去 `review_list` 查 |
| `watch --once` 输出 `dispatch=True` | 输出 `dispatch=False`，不生成 inbox 转交文件 |

**对比**：`addmodel` 那个 hub **配了**它（`-Backend inbox`），所以那边能生成
`.addmodel/review-inbox/R_xxx.txt`。**但 mimo 这几轮都是自己主动查到评审的**
（review 事件里能看到它调 `review_list`），所以**空着也能协作，只是不自动**。

**建议**：若 mimo 常驻、你知道有活时让它去查，**保持为空即可**（少一层自动化的黑箱）；
若希望"提交即推送"，可配成——

```json
"auto_review_cmd": "powershell -NoProfile -ExecutionPolicy Bypass -File <协作工具目录>\\auto-review.ps1 -ReviewId {review_id} -Root {root} -Backend inbox"
```
