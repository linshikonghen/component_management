# 元器件管理 — 规格说明书

> 版本：**v2.2**（比对新增「缺料人工匹配 + 可选字段同步」，见 FR-2.14 / FR-2.15 / FR-2.16；用户 2026-10-17 需求）
> 日期：2026-10-17（v2.2；初稿 2026-10-15）
> 定位：**本地离线**的电子元器件库存管理工具，面向个人/小团队 PCB 打样与采购
> 信源声明：**本文件是验收的唯一信源**。凡与本文冲突的实现，以本文为准。
> 变更沿革见 §9 末尾「版本沿革」。

## 1. 项目概述

### 1.1 要解决的问题

手工维护元器件库存时，反复发生的三件事：

1. **同一颗料重复买**——库里有，但不知道。
2. **数量对不上**——BOM 说 8 个，库里有几个说不清。
3. **买回来看错规格**——耐压/材质不对（如需要 50V 买成 25V）。

本工具让"打样前查一遍库"变成一件小事：**导入 BOM → 系统告诉你还缺什么 → 只补缺的**。

### 1.2 核心价值（一句话）

> **把 BOM 变成"要采购的清单"，且绝不重复采购库里已有的料。**

### 1.3 明确不做（边界）

- ❌ 默认不联网、不查立创/淘宝价格（离线优先）；云同步为用户显式开启的可选功能，见 FR-6.1
- ❌ 不做 PCB 设计、不做原理图
- ❌ 不做采购订单/财务
- ❌ 不做多用户 / 权限体系；云同步仅 FR-6.1 显式可选（默认关闭）
- ❌ 不做元器件参数自动识别（如自动判断"10uF/50V"的耐压值）——**由人确认**

## 2. 术语

| 术语 | 含义 |
|------|------|
| **BOM** | 物料清单，来自 EDA 工具导出（列固定 10 列，见 §4.1） |
| **条目** | BOM 里的一行，代表一种料（可能对应多个位号） |
| **器件** | 库存库里的一条元器件记录 |
| **套数** | 本次要做几块板；应入库数量 = BOM 单套数量 × 套数 |
| **本次入库量** | **人工确认后实际加进库的数量**（v1.4，可与应入库量不同，见 FR-1） |
| **关键信息** | 用于唯一识别与选型的字段（字段清单见 §5.1，判定规则见 §5.2） |
| **比对** | 拿 BOM 与库对照，算出"够用"与"缺多少" |
| **缺口** | 需求数 − 现有库存（下限 0），即还需采购的量 |
| **低库存阈值** | 每种料设置的警戒线，低于它要提示 |

## 3. 功能需求

### FR-1 BOM 导入入库

| 编号 | 需求 |
|------|------|
| FR-1.1 | 可选择一个或多个 BOM 文件（`.xlsx` / `.csv`）导入 |
| FR-1.2 | 导入时可指定**套数**（正整数，默认 1） |
| FR-1.3 | 导入**必须**先进入**人工核对界面**，逐条确认后才允许入库（见下 v1.4 说明） |
| FR-1.4 | 核对界面必须显示"BOM 原数量 × 套数 = 应入库数量"的算式 |
| FR-1.5 | 核对时发现数量与位号个数不符，必须**醒目警示**并要求人工裁决 |
| FR-1.6 | **在核对阶段（入库前）即可逐条修改**：本次入库量、关键信息、备注、低库存阈值（见下 v1.4 说明） |
| FR-1.7 | 可跳过某条（不入库），并记录跳过原因 |
| FR-1.8 | 入库前显示汇总预览：新增 N 条 / 合并 M 条 / 跳过 K 条 |
| FR-1.9 | 同一种料重复入库时，**累加数量**而非新建重复器件 |

> **v1.4 强化说明（用户明确要求，实现不得简化）**
>
> **① 人工确认是强制步骤，不是可选优化**
>
> 不得提供"一键静默导入"绕过核对界面（AGENTS.md 项目硬规则第 2 条）。
> 核对界面是**唯一**的入库通道。
>
> **② 核对阶段即可改，且改的是「本次入库量」，不是 BOM 原值**
>
> | | BOM 原值（只读） | 本次入库量（**可改**） |
> |---|---|---|
> | 含义 | BOM 单套数量 × 套数 | 实际要加进库的数量 |
> | 可否编辑 | **不可**（保持 BOM 原样） | **可**，默认=应入库数量 |
> | 改一行 8→10 的效果 | 算式仍显示 `8 × 3 = 24` | 库里 **+10**，且记录人工改过 |
>
> **语义**：BOM 是"清单说要有多少"，本次入库量是"实际收/存多少"。
> 两者常常不等（手上有现货、BOM 填错、只买一部分）。**以人工改的值为准入库**，
> **BOM 原值只作参照展示**，且**绝不回写 BOM 文件**。
>
> **③ 改动必须留痕**
>
> 凡被人工改过的条目，入库时记录：`原应入库量` + `实际入库量` + `改动标记`，
> 使事后能回答"这条为什么和 BOM 不一样"。
>
> **④ 可改的字段**（FR-1.6）：本次入库量、值、封装、耐压、材质、容差、
> 型号、厂商、库位、低库存阈值、备注。**不可改**：BOM 原数量、位号（位号是 BOM 事实）。
>
> **⑤ 校验**：本次入库量必须为**非负整数**；为 0 视同跳过并提示。

### FR-2 BOM 比对（与录入口隔离）

| 编号 | 需求 |
|------|------|
| FR-2.1 | 比对是**独立入口**，与 FR-1 的录入口完全分离，互不影响 |
| FR-2.2 | 导入 BOM 后，与库中已有器件逐条比对 |
| FR-2.3 | 比对结果分类展示：**够用（库中已有且库存充足）** / **缺料（需采购，含库存不足时的缺口）** / **疑似匹配（需人工确认）** |
| FR-2.4 | 必须能导出结果；导出内容**只含"缺料"的条目**（含库存不足时按缺口数量导出） |
| FR-2.5 | 比对结果视图、人工确认/否定、导出**绝不修改库中任何器件的任何信息**（含数量）；**唯一例外**见 FR-2.15 |
| FR-2.6 | 除 FR-2.15 的显式字段同步外，比对全过程只读，不产生库存变动记录 |
| FR-2.7 | 导出结果**必须能被立创商城 BOM 智能云表识别**（用户唯一要求，见 §4.2）；导出列结构按目标平台定，不要求与原 BOM 十列逐字一致 |
| FR-2.8 | 导出文件可自定义文件名，默认含时间戳 |
| FR-2.14 | **缺料人工匹配**（用户 2026-10-17 需求）：对「库里没有这颗料」或「疑似被人工否定」的缺料行，可人工指定库中一条器件，按该器件库存判定够用/缺料（缺口 = 需求 − 库存）；**已匹配上、只是库存不足的缺料行不提供人工匹配**。匹配关系只作用于本次比对，不持久保存 |
| FR-2.15 | **字段同步（比对侧唯一允许写库的动作）**：人工匹配后，可把 BOM 行在判定键五字段（值/封装/耐压/材质/容差）里的**有效值**（归一后的规范写法；BOM 空字段不动库里原值）同步到被匹配器件。必须**先预览"旧值 → 新值"并由人确认**；写库必须留一条变动记录（adjust，数量不变 delta=0）。选择不替换 = 仅本次匹配、库文件字节不变 |
| FR-2.16 | **疑似是中间分组**：疑似确认「同一颗」按库存归入够用/缺料，确认「不是同一颗」归入缺料；进入够用/缺料后**保留两个确认键可直接改选**，「改判」可退回疑似。未裁决的疑似不参与采购导出 |

> **v1.2 变更**：FR-2.3/2.4 由"有没有"升级为"**够不够**"——库里只有 3 个而需要
> 24 个时，旧版会漏掉缺口 21 个，违背 §1.2 "只补缺的"核心价值。比对入口需可指定
> 套数（默认 1），缺口 = 需求数 − 现有库存。
>
> ✅ **用户已于 2026-10-15 确认此行为**（答复"你的理解正确"）。**该项已冻结**，
> 后续实现不得退回"按存在与否整条剔除"的旧语义。
>
> **v1.5 收窄 FR-2.7**：原措辞"与原 BOM 列结构兼容（可再次导入 EDA）"是我**写宽了**——
> 用户明确"**我只需要立创商城可以识别，除此之外无要求**"。故删除"回导 EDA"要求，
> 不再需要第三种 `eda` 导出模式（该要求由 mimo 在 `R_dded4bac` 中按字面提出，属规格措辞
> 过宽导致的伪需求）。**导出只需满足立创可识别**（§4.2 模式一）。

> **⚠️ FR-2 与 FR-7 的入口隔离（v1.3 补充，消除歧义）**
>
> 两者都"拿 BOM 对库"，但**性质相反**，入口必须分开：
>
> | | FR-2 BOM 比对 | FR-7 出库/领用 |
> |---|---|---|
> | 是否改库 | **绝不**（FR-2.5/2.6） | **必然改**（扣减库存） |
> | 目的 | 算出"还缺什么" → 去采购 | 从库里**拿走**已备的料 |
> | 触发 | 打样**前** | 打样**时** |
>
> **实现约束**：比对结果页**不得**出现"领料/出库"按钮。领料一律从
> 侧栏「按 BOM 领料」或器件详情的「出库」进入。
>
> **理由**：若在比对页放领料入口，用户看到"库存不足"提示后顺手点一下，
> 就会在**本不想改库存**的场景下改了库存——而"比对不改库"是本工具的信任基础。

## 4. 输入输出规格

### 4.1 BOM 列结构（依据真实样例确认）

已核对 `E:\bom\` 下 4 份真实 BOM，**列结构完全一致**（立创 EDA 导出标准）：

| 列序 | 列名 | 示例 | 说明 |
|---|---|---|---|
| A | `No.` | 1 | 行号，从 1 递增 |
| B | `Quantity` | 8 | 该条目单套数量 |
| C | `Comment` | `10uF/50V X7R` | **常含规格信息**（值/耐压/材质） |
| D | `Designator` | `C1,C2,C4,C5` | 位号，逗号分隔 |
| E | `Footprint` | `C1210` | 封装 |
| F | `Value` | `10uF` | 值 |
| G | `Manufacturer Part` | `1210B106K500NT` | 厂商料号 |
| H | `Manufacturer` | `FH(风华)` | 厂商 |
| I | `Supplier Part` | `C116808` | 供应商编号（立创编号） |
| J | `Supplier` | `LCSC` | 供应商 |

**实测结论**（4 份文件全部满足）：

- `Quantity` 与 `Designator` 位号个数的**一致性 100%**
- **无合计行**，数据从第 2 行开始到末行
- 部分行 `Manufacturer`/`Supplier Part` 为空（尚未选型）

### 4.2 导出（比对结果）—— **必须能被立创商城识别**

**导出格式：`.xlsx`**（用户确认）。已核实立创商城的接收要求：

| 要求 | 依据 |
|---|---|
| 支持 `.xls` / `.xlsx` / `.csv` | [立创 BOM 智能云表帮助](https://www.szlcsc.com/help/1108.html) |
| 立创按表头**语义识别**列（如列名叫 `MPN` 也能认成"型号"），不要求列名逐字一致 | 同上（"如您的BOM原始表格中，型号列叫 MPN，系统识别到该表头，并判定该表头为型号"） |
| 立创侧固定五列：**原型号 / 原品牌 / 原封装 / 原参数 / 原C编码** | 同上 |
| 嘉立创 SMT 侧另有一套列序：`Comment / Description / Designator / Footprint / LibRef / Pins / Quantity / 编号` | [嘉立创 BOM 格式说明](https://www.jlc.com/portal/q7i49654.html) |

**导出列（两种模式，用户可选）**：

**模式一：立创商城配单**（默认，用于直接下单）

| 列名 | 来源 | 说明 |
|---|---|---|
| `型号` | `part_number` | 立创按表头语义识别 |
| `品牌` | `manufacturer` | |
| `封装` | `footprint` | |
| `参数` | `value` + `tolerance` + `voltage` + `dielectric`（+`power` / `current`，按分类取舍） | **空格分隔**（立创优先按空格拆分），**非空项连接**。**顺序以 §4.2「参数拼写规范」的立创官方示例为准**（`100nF ±10% 50V X7R`）——v1.6 裁决：本行原写 `value + voltage + dielectric + tolerance`，与下方示例及 AC-8 验收表**自相矛盾**，现按**立创规范**统一 |
| `立创编号` | `supplier_part` | C 编码，**有则立创优先按它匹配** |
| `位号` | `designator` | |
| `数量` | **`purchase_quantity`** | **需采购数量** = max(0, 需求 − 现有库存)。库中没有时=需求量；库存不足时=缺口 |

> **v1.2 关键修正**：原写的"数量 = 采购数量（含套数）"在**库存不足**时会买多——
> 库里已有 3 个、需要 24 个，正确采购量是 **21**，不是 24。故统一为 `purchase_quantity`。

**模式二：嘉立创 SMT 贴片下单**（用于在嘉立创贴片，需按其指定列序提交）

严格按官方列序：`Comment / Description / Designator / Footprint / LibRef / Pins / Quantity / 编号`

> **v1.5 名称修正**：本模式原称"嘉立创 SMT / **EDA 回导**"，但 FR-2.7 的"回导 EDA"要求
> 已删除（§3 FR-2 注），名称保留会造成误导，故改为其**真实用途**——服务**贴片下单**。
> 本模式**不承诺**能回导进 EDA。

**格式硬约束（依据嘉立创官方说明，违反会导致工厂侧识别失败）**：

| 约束 | 内容 |
|---|---|
| 位号分隔符 | **仅支持英文逗号 `,` 或空格**；`;` `\|` `。` `'` `:` `~` `>` **一律不支持** |
| 位号区间 | 仅支持 `R1-4` 形式（字母+数字-数字，起<止） |
| 单条位号长度 | ≤ 64 字符 |
| 位号大小写 | 不区分，会被转成大写比对 |
| **不贴器件** | **不能出现在 BOM 中**（如 R10 不焊，则 BOM 里不能有 R10） |
| **备注** | 工厂侧会**忽略所有备注** |
| 编号优先 | 当编号与封装描述不对应时，**以编号为准** |

> ⚠️ 由此产生一条实现要求：比对导出时**必须保证位号用逗号分隔**，若原 BOM 用了
> `;` 等不支持符号，导出前要转换并在界面提示（见 AC-8）。

**参数拼写规范**（嘉立创官方推荐，导出"参数"列时遵循）：

- 不同属性之间**用空格分隔**，如 `100nF ±10% 50V X7R`
- **必须带单位**（`nF`/`pF`/`uH`/`Ω`）——官方明确警告"千万别用数值表达法"
- 集成块型号写完整（`LM324` 与 `LMV324` 是不同器件）
- 封装名**不加**前后缀（不要 `LC-0805`、`Res_0805_张三_2019`）

## 5. 数据规格

### 5.1 关键信息字段

**用户明确要求的**：

| 字段 | 说明 | 来源 |
|------|------|------|
| 值 (Value) | 如 `10uF`、`10k` | BOM `Value` |
| 封装 (Footprint) | 如 `C1210`、`SOT-23-5` | BOM `Footprint` |
| 耐压 (Voltage) | 如 `50V` | **从 `Comment` 解析 + 人工确认** |
| 载流 (Current) | 如 `3A` | 手动录入 |
| **型号 (MPN)** | 厂商料号，如 `1210B106K500NT`；供应商编号如 `C116808` | BOM `Manufacturer Part` / `Supplier Part` |

> **Q5 已澄清（v1.1.1）**：用户原写的"信号"是**笔误，实为「型号」**。
> 这**简化了设计**——型号本就在数据模型里（`part_number` + `manufacturer` +
> `supplier_part` + `supplier`），是 BOM 的 G/H/I/J 四列，无需新增字段。
>
> 因此**删除**初稿里的"用途 `purpose`"设想与可选的 `net` 字段：
> 本工具**不做**"器件用途/网表信号"管理（那属于原理图域，见 §1.3 边界）。
>
> 该澄清与 §5.2 的唯一性规则**正好自洽**：型号是**识别该料的标签**，
> 而**不是**判定"是否同一种料"的依据——因为同一规格可有多个厂商型号（AML 模式）。

**已采纳的补充字段**（用户授权"这里补充你认为有用的其他关键信息"，故下列字段直接纳入；
均为**选填**，空值不参与唯一性判定、不进入导出参数列）：

| 字段 | 为什么有用 | 参与判定键 |
|------|-----------|-----------|
| 材质/介质 (Dielectric) | `X7R`/`C0G`/`X5R` 直接影响温漂，电容选型必看 | ✅ 是 |
| 精度/容差 (Tolerance) | `±1%`/`±10%`，电阻电容关键参数 | ✅ 是 |
| 功率 (Power) | 电阻/电感必看，如 `1/4W` | ❌ 否（但进导出参数列） |
| 载流 (Current) | 如 `3A`，用户明确要求 | ❌ 否（但进导出参数列） |
| 封装类型 (Mount Type) | 贴片/直插，影响能否手工焊 | ❌ 否 |
| 极性 (Polarity) | 电解电容/二极管方向，装反会炸 | ❌ 否 |
| 库位 (Location) | 元件盒编号，**找料时间占实际工作一半** | ❌ 否 |
| 最低库存 (Min Qty) | FR-4 的阈值（留空=继承分类默认） | ❌ 否 |
| 批次/日期 (Batch) | 追溯与老化（电解电容有寿命） | ❌ 否 |
| 数据手册 (Datasheet) | 离线存本地路径，不联网也能查 | ❌ 否 |
| 替代料 (Substitute) | 缺货时能否代用 | ❌ 否 |

> **判定键只取 5 个字段**（§5.2）：值、封装、耐压、材质、容差。其余字段是**描述性**的，
> 参与检索、显示与导出，但**不影响"是否同一种料"的判定**——否则同一颗料多录一个库位
> 就会被当成两种料。

### 5.2 器件唯一性判定规则（**已确认**）

> 这是本工具最核心的规则。

**判定键（五元组）**：

```
同一种料  ⟺  值 value + 封装 footprint + 耐压 voltage + 材质 dielectric + 容差 tolerance  全同
```

**厂商料号（MPN）不参与判定**——同一规格不同厂商视为**同一种料**，MPN 作为该料的
「可用厂商料号列表」附加信息保存。

**行业依据**（用户要求"评判标准要正确"，故检索核实）：

1. **无源器件的等效性由参数组共同决定**，而非单个值。厂商目录把
   *Series / Dielectric / Size / Capacitance / Tolerance / Rated voltage* 并列为
   电容的识别参数组（[Passive Component 产品目录](https://www.passivecomponent.com/wp-content/uploads/Catalogue/Product_Guide.pdf)、
   [Knowles AEC-Q200 目录](https://www.knowlescapacitors.com/getmedia/42b271af-4d0c-4e0f-a44b-c6089ed506cd/KNO-AEC-Q200_Catalog_09-24_R13)）——
   **这直接说明"容差"必须进入判定键**（初稿漏了它，已补）。
2. **器件库的通行做法是「一条器件记录 ↔ 多个厂商料号」**，即 AML（Approved Manufacturer List）/
   AVL 模式，而非按 MPN 建条：
   "A relational database schema allows multiple manufacturer part numbers to be associated
   with a single component record"
   （[Cadence: Managing Your Component Library for Supply Chain Resilience](https://resources.pcb.cadence.com/pcb-design-and-analysis-center/col/pcb-design-and-analysis-center/managing-your-component-library-for-supply-chain-resilience)）
3. Oracle Agile PLM 的 AML 校验流程同样把「组件」与「厂商料号」分层
   （[Oracle Agile PLM aXML/AML 校验](https://docs.oracle.com/cd/E15366_07/otn/pdf/user/E16486_03.pdf)）。
4. 专利文献亦指出：**去重不能简单依靠型号是否重复**，因为同一型号不同厂家信息不同，
   应整条记录比对（[CN115080587B](https://patentimages.storage.googleapis.com/64/08/12/ac7dff4f029a03/CN115080587B.pdf)）。

**推论（确定方案 A 是对的）**：
- 同规格不同厂 = **一种料，多个 MPN**（便于用替代料）
- 因此**不需要**"疑似同一规格"的中间态（方案 C 被否）
- 也不需要按 MPN 严格建条（方案 B 被否）

> 注意：上述"不需要疑似同一规格"针对的是**入库建条**（去重）。
> **比对场景**（FR-2.3）仍保留"疑似匹配"——因为 BOM 行的键字段可能缺失
> （如未给容差），此时无法精确匹配，需人工裁决。

**单位归一化（判定前必须做）**：

| 原始 | 归一为 |
|---|---|
| `0.1uF` / `100nF` | `100nF` |
| `1k` / `1kΩ` / `1000Ω` | `1kΩ` |
| `4.7uF` / `4700nF` | `4.7uF` |
| 大小写、空格 | 统一小写、去空格 |

> `100` 这类纯数字**不做自动推断**（可能是 10Ω 也可能是 100Ω）——按嘉立创官方建议，
> 缺单位的记入"待确认"并提示补全（[嘉立创 BOM 格式说明](https://www.jlc.com/portal/q7i49654.html)）。

> **v1.3 补记：xlsx 写入是未验证环节**
>
> 本项目**读取** xlsx 已实测通过（纯 Node 零依赖，见 plan §1.3），但**写入** xlsx 尚未验证——
> 需手工拼接 zip 容器 + XML。这是本工程**风险最高的实现点**。
>
> 因此 AC-8 分两级验收：
> 1. **内部**：导出后用自己的读取器读回，逐格比对（T13b 即可完成）
> 2. **外部**：真文件上传立创（**唯一**能证明"立创可识别"的方式，需用户执行）
>
> 若外部验收失败，回退方案：改用 `.csv` 导出（立创明确支持 `.csv`，见 §4.2）。

## 7.5 FR-8 按对账单入库（v1.7 新增，用户 2026-10-16 需求）

> **定位**：立创商城会导出「物料明细对账单」（`.xls`），里面**带着 BOM 里没有的参数**——
> `商品名称` 写作 `100nF ±10% 100V 编带`，即 **值 / 容差 / 耐压**。
> 用户要的是：**直接按订单入库**（订购数量 = 入库量），顺带把这些参数补进库里。
> **边界（用户明确）**：这条路径**只用于入库**——**导出与比对一律不动**。

| # | 规则 | 说明 |
|---|---|---|
| FR-8.1 | 输入只认**立创对账单 `.xls`** | 真 BIFF8 老格式，零依赖读取（`xls_biff.js`）。表头缺任一关键列 → **明确报错**，绝不猜哪列是数量（猜错就是错账） |
| FR-8.2 | 只取 **H–L 列** | 商品类型 / 商品名称 / 商品型号 / 封装格式 / 订购数量（更早的订单级列不读） |
| FR-8.3 | 匹配键 = **商品类型 + 商品名称(值/容差/耐压) + 商品型号 + 封装** | **不用品牌、不用立创 C 编码**（同型号可能从别处买、厂商不同；C 编码是立创特有的） |
| FR-8.4 | 分三桶：**严格命中 / 疑似 / 新增** | 疑似 = 型号+封装+值相同但参数有差异或**库里缺项**（BOM 建的器件没有容差/耐压，实测 68/68 行为空）→ **必须人工裁决**，绝不自动合并 |
| FR-8.5 | 入库量 = **订购数量**；新建器件**不写位号** | 对账单没有位号（该字段保留给 BOM 路径）。补字段沿用既有约定：**只补空、不覆盖** |
| FR-8.6 | 分类以**商品类型**为准（比位号前缀更准），位号仅参考 | 阈值表按前缀键建 → 由商品类型推「阈值键」（映射不到落 `_default`，**不猜**；核对表里显示出来供人核对） |
| FR-8.8 | **核对表可人工修改**（用户 2026-10-16 要求） | 可改：本次入库量（默认=订购数量）、值、容差、耐压、封装、商品型号；只读：商品类型、阈值键、订购数量（对账单事实）。**改动必须随决定提交并落库**（否则是假编辑），且**留痕**（行标记 + 汇总报 edited_count） |
| FR-8.7 | 必须经**人工核对闸门**才能入库 | 无决定即拒绝（延续 FR-1.3：不得静默入库）；留痕写 `movements`（来源=对账单 + 订单号 + 行号） |

> **验收标准（AC-10）在界面接通后随见证一起补**：本项目 AC 覆盖率审计要求**每一行 AC 都有可跑的见证**，
> 先把 AC 写在没有见证的状态会让审计红。所以 v1.7 只登记需求，AC-10 行与端到端见证在 T48 一起落。
