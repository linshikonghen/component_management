# 元器件管理

一个**完全离线**的本地小工具：把立创商城下的 BOM 变成"这次要买什么"，并且**绝不重复采购库里已经有的料**。

- 零 npm 依赖（除本机已装的 Electron），**没有任何网络请求**——断网可用
- 数据就三个 JSON 文件放在本地，随时可整库备份/恢复
- 导入 BOM 必须**逐条人工核对**才能入库（不给"一键静默导入"）

> 规格：`docs/spec.md`（WHAT，验收唯一信源）· 方案：`docs/plan.md`（HOW，技术约束）
> 本文件是**给人看的使用说明**。

---

> 架构与分层（目录职责、依赖规则、检索规范、测试分层、打包流程）见 [`docs/architecture.md`](docs/architecture.md)。

## 一、怎么启动

**前提**：本机已装 Electron（全局 42.5.0）。本项目不装任何 npm 包。

### 方式一：桌面快捷方式（推荐）

```powershell
cd <项目根>
powershell -ExecutionPolicy Bypass -File tools\make-shortcut.ps1
```

跑完桌面上会出现「元器件管理」，**双击即用**。可选参数：
`-ShortcutDir <目录>`（放别处）、`-ElectronPath <exe>`（手动指定 Electron）、`-Name <名字>`。

> **如果你看到的是一份已经在仓库里的快捷方式**：`元器件管理.lnk` 就在项目根目录
> （生成它的是同一个脚本，只是目标目录换成了项目目录）——**把它拖到桌面**即可，
> 它里面的目标/工作目录/图标都是绝对路径，放哪儿都能用。
> 之所以不预先放在桌面：写桌面需要**越过沙箱**（写工作区以外一律被拒），
> 所以那一步得由你执行一次（脚本或拖动都行，之后不用再管）。
> **图标为什么必须放在项目之外**（2026-10-16 实测）：把 `.ico` 放在本工作区里时，
> **Explorer 的图标渲染路径读不到它**，快捷方式会退回到 Windows 的通用图标（白纸+箭头）——
> 这和图标文件本身无关（同一个文件用 Pillow 读、让 shell 直接读、逐字节校验都正常）。
> 所以脚本会自动把图标复制到 `%LOCALAPPDATA%\component_management\icon.ico` 并**用那一份**，
> 复制后还会做字节一致性校验；万一复制失败会明确告诉你"可能显示为通用图标"。
> 三组对照（工作区内 / 工作区外 / 第三方 exe·dll）与验证方法都写在 `docs/plan.md` §11。

> 若哪天双击没反应，直接双击 `启动-兜底.cmd` 也能起——它专门处理
> `ELECTRON_RUN_AS_NODE` 被设成 1 时 electron.exe 会静默退出的坑。

### 方式二：命令行直接跑

```powershell
cd <项目根>
& "<用户目录>\AppData\Roaming\npm\node_modules\electron\dist\electron.exe" .
# 或者 npm start（如果本机 npm 能找到 electron）
```

### 方式三：启动自检（起不来时用）

```powershell
& "<electron.exe>" . --smoke --smoke-out=D:\smoke.json
Get-Content D:\smoke.json     # 期望 {"ok":true,"window_ms":…,"channels":16,"nfr1_ok":true}
```

失败时会写 `{"ok":false,"stage":"did-fail-load" / "render-process-gone" / "uncaughtException"}`，
**"起不来"和"起来了但白屏"能分开**。

## 二、典型流程（第一次用照这个顺序走）

| 步骤 | 在哪 | 要点 |
|---|---|---|
| ① 导入 BOM | 左侧「导入 BOM」 | 选文件 + 套数 → 解析。**解析不改任何数据** |
| ② **人工核对** | 同上，第 2 步 | 逐条看一眼；**本次入库量可改**（BOM 原值只读）；数量与位号个数不符的行会标红，**必须勾"已核实"或改为跳过**才允许入库 |
| ③ 入库 | 核对表底部「确认入库」 | 汇总显示 新增/合并/跳过，**三数之和 = 条目总数**；改过数量的会留痕 |
| ④ 比对 | 左侧「比对」 | 选文件 + 套数 → 三组结果（够用 / 缺料 / 疑似）。**这一页只读** |
| ⑤ 导出采购清单 | 比对页底部 | 立创配单 / 嘉立创 SMT；只导**缺料**；缺料为 0 时会阻止导出空表 |
| ⑥ 领料 / 出库 | 左侧「领料」 | 手动出入库（填原因）或按 BOM 一次性扣减；库存不足默认**整单拒绝** |
| ⑦ 手动录入 | 左侧「手动录入」 | 不依赖 BOM 也能录料；点「库存」页某行的「编辑」可直接改 |
| ⑧ 阈值与设置 | 左侧「设置」 | 14 类默认阈值可改；**改完未设个体阈值的器件立刻按新值判定** |
| ⑨ 备份 | 左侧「备份」 | 整库备份；恢复会覆盖当前库，**但覆盖前会自动另存一份** |

## 三、七个页面速查

| 页面 | 读/写 | 一句话 |
|---|---|---|
| 库存 | 写（编辑/删除/导出） | 器件列表：可排序、搜索、编辑、删除、**导出库表**；低库存标红 |
| 导入 BOM | 写（仅"确认入库"那一下） | 三步向导；核对表是**唯一的入库通道** |
| 比对 | **只读** | 三组分类 + 缺口合计 + 导出采购清单；**没有任何领料入口**（入口隔离） |
| 手动录入 | 写 | 录入/编辑单条器件 + 详情 + **变动历史**（时间倒序） |
| 领料 | 写 | 手动出入库、按 BOM 领料；每笔都写变动记录 |
| 设置 | 写 | 分类默认阈值、低库存清单、数据目录（需确认） |
| 备份 | 写 | 整库备份 / 恢复（需确认，自动留一份） |

**需要人工确认的操作**（点了会要求确认，不会静默执行）：删除器件、恢复备份、更改数据目录。

## 四、数据在哪

```
data/
├── parts.json       器件库
├── movements.json   变动记录（任何数量变化都留痕：何时/多少/为什么）
└── settings.json    设置（分类默认阈值、数据目录、导出模式）
```

- **数据目录可改**（设置页，需确认）：改完之后应用去新目录读写，**旧目录的数据不会自动搬过去**——
  要搬家请先用「备份」导出、再到新目录「恢复」导入。界面上有这句警告并且必须勾选确认。
- **备份语义**：备份 = 在指定目录下新建一个带时间戳的目录，把三个文件复制进去（另附 `manifest.json`）。
  恢复 = 用备份覆盖当前库；**覆盖前自动把当前状态另存一份**（`.pre-restore-<时间戳>`），恢复错了还能回去。
- **完全离线**：源码里没有任何对外请求的调用，页面 CSP 是 `connect-src 'none'`，
  主进程还在运行时拦截 http/https/ws/wss/ftp。**想联网也没有通道。**

## 六、已知限制与未完成项（如实列）

| 项 | 说明 |
|---|---|
| **外部验收：立创已识别成功** | 导出文件**上传到立创商城 BOM 智能云表，识别成功**（用户实测，2026-10-16）。这条是 AC-8 的**外部一级**验收，只能在真站上做——记录在 `.addmodel/human-signoff.json` 里（**可撤销**：删掉记录，下次跑验收它自动回到"待人工"） |
| **还需你点一下：双击桌面快捷方式** | 快捷方式已生成并放到桌面（`元器件管理.lnk`，用 COM 读回校验过：目标/工作目录/图标都对）。**双击出窗口**这个动作只能你在自己桌面上做——沙箱里 Electron 起不来（已归因：最小 Electron 应用同样 `0x80000003`）。做过之后在 `.addmodel/human-signoff.json` 里把 `ac6_double_click_window` 也签收掉，验收就会变成 **PASS 42 · 待人工 0** |
| **界面行为是"桩上跑过"而非"真窗口点过"** | 七个页面的装配逻辑已用假 DOM 真跑（见上）；但真窗口里的渲染、字体、布局仍需你在桌面上看 |
| **导出没有"另存为"对话框** | 只能留空用默认名（含时间戳）或手输路径。评估后**不新增通道**（理由见 plan §11"实现期补记 3"） |
| **不提供批量改数量** | 改数量只能逐条编辑——批量改属"需人工确认"操作，索性不做 |
| **两处 spec 自相矛盾待裁决** | ①AC-4「阈值留空=不提示」vs FR-4.8/AC-9「留空=继承分类默认」；②附录 A/B 的行数与"一致性 100%"与实际数据不符。**spec 是验收唯一信源，未确认前我不改它** |
| **24 件提交尚未评审** | 按协作规则必须由**另一位**代理 approve（禁止自审），目前全部停在 `in_review` |
